# ส่งข้อความถึงผู้เช่า

ผู้ใช้เลือกยกเลิก cron และใช้การส่งด้วยแอดมินเมื่อ 17/10/2569

## การใช้งาน

1. เจ้าของหรือแอดมินเปิด `/admin/messages`
2. เลือกทุกห้องในสัญญาที่ใช้งาน รายห้อง หรือห้องที่มีบิลรอชำระ
3. เลือกแม่แบบหรือพิมพ์ข้อความ ตรวจตัวอย่างก่อนกดส่ง
4. ดูผลส่งและประวัติ LINE ล่าสุด 100 รายการ รวมข้อความแอดมินและผลตรวจสลิป
5. กดส่งซ้ำได้เฉพาะ `failed` และ `skipped` ที่มีข้อความเดิมบันทึกไว้

ตัวแปร `{ห้อง}`, `{ยอดค้าง}`, `{ครบกำหนด}` เติมจากฐานข้อมูลฝั่ง server ใหม่ก่อนส่ง ยอดค้างรวมบิล `issued`/`overdue` และไม่รวมบิลที่ส่งสลิปแล้วรอตรวจ วันครบกำหนดเป็นวันที่เร็วที่สุดของบิลเหล่านี้

## ข้อมูลและสิทธิ์

- ทุก Server Action ตรวจ session และ role `owner`/`admin` ก่อนใช้ service client
- `notifications` เก็บผู้รับ ข้อความ ผู้สร้าง เวลา สถานะ ข้อผิดพลาด และเวลาส่งสำเร็จ
- ส่งผ่าน LINE ถึงผู้เช่าแต่ละคนในห้อง ไม่ส่งไปกลุ่ม LINE
- ไม่มี token หรือไม่มี LINE user ID จะบันทึก `skipped` โดยไม่เรียก LINE
- ต้องติดตั้ง migration `20261018000002`–`20261018000007` และ migrations ก่อนหน้า ก่อนเปิดใช้หน้าใหม่นี้; Cloud ของโครงการ apply แล้ว
- Migration สำหรับ invite code `20261017132926_accept_invite_code_once.sql` เป็น dependency ของการยืนยันผู้เช่าทาง Bot. เนื่องจาก timestamp เก่ากว่า migration `20261018000000`/`000001` ที่ Cloud ลงแล้ว ให้ใช้ `supabase db push --linked --include-all` เมื่อนำไปลง environment ที่ยังไม่มี migration นี้

## ข้อจำกัด

- ไม่มีการเตือนตามเวลาหรือส่งซ้ำอัตโนมัติ แอดมินเป็นผู้กดส่ง
- `sent` หมายถึง LINE รับคำขอ ไม่ยืนยันว่าผู้รับอ่านแล้ว
- การส่งหลายห้องทำในคำขอเดียว จำกัดพร้อมกัน 5 ผู้รับ หากคำขอถูกตัดก่อนเสร็จ อาจส่งได้บางส่วน ตรวจประวัติก่อนส่งใหม่
- การกดสร้างข้อความใหม่แต่ละครั้งเป็นการส่งใหม่ ปุ่มถูกปิดระหว่างรอผลในฟอร์มเดียว แต่ไม่ได้ป้องกันแอดมินคนอื่นสร้างข้อความเดียวกัน
- รายการ `pending` ที่ค้างหรือการส่งที่ timeout ต้องตรวจผลก่อนส่งใหม่เพื่อหลีกเลี่ยงข้อความซ้ำ ไม่มีปุ่มส่งซ้ำสำหรับ `pending`
- ผลตรวจสลิปยังแยกจากการส่ง LINE การส่งล้มเหลวไม่ย้อนสถานะการเงิน
- งานนี้ยังไม่มีหลักฐานส่ง LINE จริงหรือทดสอบหน้าเว็บกับบัญชีจริง
